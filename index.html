03

Create the integration record

Where: SetupIntegrationManage IntegrationsNew
  • Enter a name your admins will recognise, such as Order Sync Service.
  • On the Authentication tab, under OAuth 2.0, check Client Credentials (Machine to Machine) Grant.
  • Under Scope, check RESTlets. Also check REST Web Services if you'll call the record API.
  • Uncheck Token-Based Authentication and Authorization Code Grant if you don't use them.
Copy the Client ID now. NetSuite shows the client credentials only once, right after you save. If you lose them, you have to reset them on the record.
04

Generate a key pair

You need two files: private.pem, which stays with your app, and public.pem, which you upload to NetSuite. NetSuite accepts RSA keys of 3072 or 4096 bits. Generate them in this page or with OpenSSL.

Option A: Generate in your browser (testing only)

Use this only for testing. For sandbox or production integrations, we recommend generating your own certificate with OpenSSL (Option B) on the machine or secret store where the key will live. Keys from this page pass through your browser and downloads folder, which is fine for a quick test but not for a key that guards real data.

This uses your browser's built-in Web Crypto and the @peculiar/x509 library. The key is created on your device and never sent anywhere.

For testing only. Keep private.pem secret and upload only public.pem to NetSuite in step 5. Before going live, replace this pair with a certificate you generate yourself, then revoke this one's mapping. The keys aren't stored anywhere, so reloading this page discards them.
Use the same code in your own app

Option B: OpenSSL

Run this on any machine with OpenSSL.

The key isn't tied to a machine. Any server holding private.pem can connect, so treat it like a password. NetSuite caps certificate validity at two years. Note the expiry date so you can rotate the key in time.
Calling from SuiteScript in another NetSuite account? Generate an RSA-PSS key with OpenSSL instead, because NetSuite documents SuiteScript PS256 signing with that key type. The browser generator creates a standard RSA key. The SuiteScript (other account) tab in step 8 has the command.

Map the certificate

Where: SetupIntegrationOAuth 2.0 Client Credentials (M2M) SetupCreate New
  • Entity: the integration user from step 2.
  • Role: the integration role from step 2.
  • Application: the integration record from step 3.
  • Certificate: upload public.pem. Never upload private.pem.

After you save, copy the Certificate ID from the list. Your app sends it as the JWT kid header.

06

Deploy the RESTlet

Skip this step if your RESTlet already exists. Otherwise, here is a minimal SuiteScript 2.1 RESTlet: upload it to the File Cabinet, then create a script record and a deployment for it.

  • Set the deployment Status to Released. Testing only lets the script owner call it.
  • Under Audience, add the integration role, or select All Roles.
  • Note the script ID and deployment ID, for example customscript_order_sync and customdeploy_order_sync. Numeric internal IDs work too.

Call the RESTlet

Every example does the same three things. It signs a PS256 JWT with your private key and exchanges it for an access token, caches that token until a minute before it expires, and POSTs JSON to the RESTlet with it. Pick a language:

Code

The token is cached in memory. Each access token lasts about 60 minutes, so the examples reuse it and only request a new one a minute before it expires. A lock stops parallel calls from requesting several tokens at once. If you run several app instances, each keeps its own token, which is fine. To share one, store it in Redis or a similar cache with the same expiry.

Troubleshooting

invalid_scope on the token call
The integration record doesn't have RESTlets checked, or the JWT asks for a scope the record lacks.
invalid_grant or invalid_client
The client ID, certificate ID or key doesn't match the mapping, the certificate has expired or been revoked, or the server clock is off by more than a few minutes.
401 INVALID_LOGIN on the RESTlet
You sent the request to the suitetalk host instead of restlets, or the token has expired.
403 / INSUFFICIENT_PERMISSION
The deployment isn't Released, the role isn't in its Audience, or the role lacks a permission the script uses.
SSS_MISSING_REQD_ARGUMENT or "invalid script"
The script or deploy query parameter is wrong. Copy them from the deployment record.
The RESTlet receives an empty body
Set Content-Type: application/json on the RESTlet request.
DNS error, host not found
Check the account ID in the hostname: lowercase, with _ changed to -, as in 1234567-sb1.
!

Keeping the key safe

  • Store private.pem in a secret manager, and never in Git or a container image.
  • Use a separate key and certificate mapping for each environment, such as sandbox and production.
  • To rotate without downtime, map a new certificate alongside the old one, switch the app over, then revoke the old mapping.
  • If a key leaks, revoke its mapping straight away. Tokens already issued stop working within about an hour.
  • Never log the token request. It contains the signed assertion.
Endpoints: token at https://<account>.suitetalk.api.netsuite.com/services/rest/auth/oauth2/v1/token. RESTlets at https://<account>.restlets.api.netsuite.com/app/site/hosting/restlet.nl. Check NetSuite's Help Center for changes in newer releases.
